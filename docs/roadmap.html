Roadmap

The order comes from evidence: what hurt while writing Candor's own compiler in Candor. Each milestone has a concrete way to tell it's done.

Ground rules for every change:

1. It lands in both compilers, the JS reference and the self-hosted candorc.

2. Both backends and both compilers stay byte-identical on every test, and the bootstrap still reaches its fixed point.

3. Each new rule comes with a diagnostic that says what to change, not just what's wrong.

Done

v0.1: Core language done

Effects in signatures, typed holes, requires/ensures/example, labeled ends, no implicit conversions, trapping arithmetic, value semantics, exhaustive match. Two backends (instant JS and native C) held to byte-identical output by differential tests.

v0.2: Self-hosting done

inout parameters marked at the call site, borrowed arguments with copy-on-escape, string, file and argument built-ins, and candorc (the compiler in Candor) reaching a bootstrap fixed point. Then the first fixes from the field notes: ==/show on payload-free enums, top-level constants, and pop.

Next

v0.3: Modules next

use "lexer.cnd", with each file checked as its own unit and diagnostics that name the real file and line. Names stay globally unique (no shadowing across modules), keeping "every name means one thing".

Done when: candorc is split into real modules, selfhost/build.sh is deleted, and its errors cite parser.cnd:120 instead of a line in a concatenated file.

v0.4: Distinct types

type TyId = distinct Int: same representation, but not interchangeable with Int or with another distinct type. In candorc today, type ids and AST node ids are both Int, and mixing them up type-checks.

Done when: candorc uses TyId, NodeId and TokIdx, and swapping any two is a compile error.

v0.5: Generics and error propagation

Generic records, enums and functions, compiled by monomorphization in C. In the standard library: Option[T] and Result[T, E], with a visible way to propagate errors (for example try parse_expr(inout p)) inside functions that return Result.

Done when: the failed flag disappears from candorc's parser, read_file returns a Result instead of trapping, and generic code produces readable errors.

v0.6: Memory

Reference counting with copy-on-write in the native backend. Memory gets freed, and the remaining eager copies (when a value escapes, or on let b = a) become lazy.

Done when: the binary-trees benchmark peaks under 50 MB (453 MB today), long-running loops use bounded memory, and no benchmark gets slower by more than 10%.

v0.7: A typed AST for candorc

With generics and data-carrying enums, the compiler's arena of generic nodes becomes separate types for statements, expressions and types. The big dispatch functions become exhaustive matches, so adding a node kind fails to compile until every pass handles it.

Parallel tracks

Research: can models actually write Candor well?

This is the question behind the whole project. Give a fresh model only the language guide, then have it solve a fixed task set in Candor and in TypeScript or Python. Measure:

  • whether the code is correct on the first try;
  • how many attempts it takes to reach correct code;
  • which bugs Candor's rules catch: effects, holes, contracts, traps;
  • which Candor rules the model trips over.

Publish the results here, including the unflattering ones.

Tooling

  • candor fmt, a single canonical layout;
  • candor test on the native backend;
  • --json for run and test output;
  • an index of error codes, with a page per code;
  • editor syntax highlighting and a minimal language server (diagnostics and holes).

Performance

  • A Ryu-style shortest float printer. Native show(Float) is about 2 µs per call today, which makes the strings benchmark slower native than on JS.
  • Cheaper overflow checks on the JS backend's integer-heavy loops. Collatz is 13× slower there than native.

Standard library

Generic maps and sets (replacing candorc's hand-written StrMap), a string builder, sorting, and file and process I/O that return Result. The library stays small: one obvious way to do each thing.

Long term: Candor all the way down

Give candorc a JavaScript backend so the whole toolchain is written in Candor, and retire the JS front end. Because candorc could then compile itself to JavaScript, the self-hosted compiler could run in the browser, as an online playground on this site.

Not planned

  • Operator overloading, implicit conversions, truthiness, macros. Each adds a second way for code to mean something, and that's where models get confused.
  • Exceptions. Errors will be values (Result) that the signature makes visible.
  • Terseness for its own sake. Verbosity is cheap for the writer, and explicitness is what the reviewer needs.
