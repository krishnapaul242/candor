Candor compiles Candor

selfhost/candorc.cnd is a complete Candor compiler written in Candor: a lexer, a parser, a checker with every diagnostic, and a C backend. It builds itself, and the result builds itself again, identically.

The bootstrap

StageWhat happens
0The JavaScript reference compiler, the seed.
1Stage 0 compiles candorc.cnd into a native candorc1.
2candorc1 compiles candorc.cnd, producing stage2.c, which builds candorc2.
3, 4candorc2 and then candorc3 each compile candorc.cnd again.

The C from stages 2, 3 and 4 must be byte-identical. That is the fixed point: the compiler carries itself, and successive generations stop changing. A compiled compiler then builds itself in about 10 ms.

How it's checked

selfhost/test.sh          # stage 1, comparisons, bootstrap
FULL=1 selfhost/test.sh   # ...and every benchmark too
  1. Behavior: every program in tests/run, examples and bench gives identical stdout, stderr and exit code when compiled by candorc and when run by the reference compiler.
  2. Diagnostics: every file in tests/errors gets word-for-word identical errors, hints and caret positions from both compilers. One file alone produces 46 different errors.
  3. Fixed point: stages 2, 3 and 4 match byte for byte.

Every language change goes into both compilers, and the suite keeps them in agreement. So the language can now evolve using itself.

Field notes

The point of self-hosting was to learn whether the language holds up for a real program. The full notes are in selfhost/NOTES.md. The short version:

What worked

  • inout plus borrowed arguments. The whole compiler threads its state through inout parameters. Every mutation is visible at the call site, and read-only helpers cost nothing.
  • The type checker as a refactoring tool. Moving the compiler's internals from strings and magic numbers to enums touched about 330 places, using a regex script. The checker reported every site the script got wrong. After those were fixed, the rewritten compiler passed everything and reached a new fixed point on the first run.
  • Labeled ends stayed readable landmarks across about 4,000 lines.

What hurt, and what changed because of it

Pain pointStatus
Enums couldn't be compared, so the AST used strings for its kindsFixed: == and show on payload-free enums. The AST now uses NodeKind.
No constants, so type ids were magic numbersFixed: top-level constants (T_INT, …).
No array popFixed: pop(xs).
No modules: six files joined with catNext on the roadmap
No error propagation: a failed flag threaded everywherePlanned: generics with Result[T, E]
Type ids are plain Ints, interchangeable with node idsPlanned: distinct types
No closuresOpen question

An honest caveat. candorc was a port of a design first written in JavaScript, which is easier than designing a compiler from scratch. The clean first runs say more about the porting than about the language. The pain points are the more trustworthy signal.
